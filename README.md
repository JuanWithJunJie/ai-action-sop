# AI-SOP Vision | 手机制造智能SOP系统

> 面向手机制造工厂的 AI-SOP 动作识别系统。
> 通过摄像头实时识别工位上的标准操作步骤，自动判断 SOP 执行顺序、合格率，并记录全程事件。

---

## 系统概述

在手机制造流水线上，每个工位都有标准操作流程（SOP）。本系统通过摄像头对准工位，自动识别操作员当前执行的动作步骤，判断是否按 SOP 顺序执行，并在每个步骤完成后自动截图留档、记录日志。

### 核心能力

- **实时动作识别**：MediaPipe 手部关键点 + LSTM 时序分类
- **多周期循环检测**：D1→D2→D3→D4 走完后自动开启下一轮，支持连续生产
- **超时跳过机制**：某步长时间未命中自动跳过，避免卡住生产线
- **步骤截图留档**：每个步骤完成时自动截取对应画面，显示在步骤卡片中
- **生产统计**：合格率环形图、合格/超时/总数统计、事件日志
- **工业指挥中心风格 GUI**：深色主题、无边框窗口、字体自适应缩放

## 技术栈

### 模型与算法层

| 组件 | 作用 | 说明 |
|------|------|------|
| **MediaPipe Hands** | 手部关键点 | 最多 2 只手，每只 21 个关键点三维坐标 (x,y,z) |
| **LSTM** (PyTorch) | 时序动作分类 | 输入 126 维手部特征，输出动作类别概率 |
| **多尺度时序窗口** | 抗抖动 | 48/72/96 帧窗口投票融合，兼顾响应速度和稳定性 |

### 特征向量（126 维）

```
手部关键点 (2手 × 21点 × 3坐标 = 126维)
```

| **PyQt5** | 桌面客户端 GUI（工业指挥中心风格） |
| **OpenCV** | 视频读取、帧处理、绘制 |

## 快速开始

### 1. 安装依赖

```bash
# 创建虚拟环境（需 Python 3.10~3.11）
python -m venv .venv
.venv\Scripts\activate

# 安装 PyTorch (CUDA 12.1)
pip install torch==2.2.2 torchvision==0.17.2 --index-url https://download.pytorch.org/whl/cu121

# 安装其余依赖
pip install -r requirements.txt
```

### 2. 启动桌面客户端

```bash
python ai_sop_gui.py
```

GUI 操作：
1. 点击「导入视频」选择 `.mp4` 文件
2. 调整 LSTM 阈值（默认 0.15）
3. 点击「开始分析」启动实时推理
4. 步骤完成后自动在卡片中显示截图

### 3. 训练自定义动作（可选）

如果默认模型效果不理想，可重新训练，详见下文「训练流程」章节。

---

## 训练流程（自定义动作）

### Step 1：放置视频

将训练视频放入 `video/` 目录。

### Step 2：提取特征

```bash
python extract_features.py
```

逐帧提取 MediaPipe 的 126 维特征，保存到 `train_data/features/*.npy`。

### Step 3：标注 timeline

编辑 `train_data/timeline.csv`，标注每个动作的起止时间：

```csv
video_name,step_id,step_cn,start_sec,end_sec
20260807-154738.mp4,D1,取料,3.000,3.500
20260807-154738.mp4,D2,撕膜,4.600,5.000
...
```

> 时间码支持小数秒（精度到帧级别，30fps 下 0.033s）。

### Step 4：（可选）自动伪标注

如果只标注了部分视频，可以用 KNN 特征相似度自动给未标注区间打标签：

```bash
python auto_label.py
```

输出 `train_data/timeline_auto.csv`，在 `train_lstm.py` 中切换使用。

### Step 5：训练 LSTM

```bash
python train_lstm.py --epochs 80
```

训练特性：
- **数据增强**：高斯噪声 + 时间扭曲 + 特征缩放（3 倍扩充）
- **类别权重**：自动平衡各类样本数差异
- **正则化**：dropout=0.4 + weight_decay=1e-4，防止过拟合
- 模型保存到 `lstm_runs_fine/best_lstm_fine.pt` + `config.json`

### Step 6：验证

```bash
python ai_sop_gui.py
```

导入视频，观察 D1→D2→D3→D4 多周期循环推进效果。

## GUI 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **LSTM 阈值** | 0.15 | 动作确认置信阈值。高=更稳但可能卡住，低=更易通过 |
| **确认帧数** | 4 | 连续命中多少帧才算步骤完成 |
| **超时跳过** | 6.0s | 某步等待超时自动跳过，避免卡住产线 |
| **显示关键点** | 开启 | 是否在画面上显示 MediaPipe 手部关键点 |
| **保存截图** | 开启 | 步骤完成时自动截取画面 |
| **保存日志** | 开启 | 导出 result.json + events.csv |

## 关键机制

### 多尺度投票
同一时刻在 48/72/96 帧三个窗口长度上分别预测，投票融合，降低偶发抖动。

### 顺序约束
系统按 D1→D2→D3→D4 顺序推进，不能跳步。每步需达到置信度阈值并连续命中确认帧数才算完成。

### 超时跳过
若某步在 6 秒内仍未命中确认，自动标记为「超时跳过」并推进到下一步，避免产线卡住。

### 多周期循环
D1→D2→D3→D4 全部完成后自动重置，开始下一轮检测，支持连续生产场景。

### 字体自适应
GUI 根据窗口大小自动缩放字体，最大化后文字自动放大，适配不同分辨率屏幕。

## 技术架构选型

| 层 | 技术 | 说明 |
|---|---|---|
| UI 层 | PyQt5 + QSS + QPainter | 渲染界面、显示帧、用户交互 |
| 推理层 | QThread + MediaPipe + LSTM | 逐帧推理、步骤推进、事件记录 |
| 数据层 | JSON + CSV + 截图 | 结果存储、日志导出、截图留档 |
| 视频源 | OpenCV VideoCapture | 视频文件 / RTSP 流 / USB 摄像头 |

**选择 PyQt5 单体架构的理由**：
- 帧渲染延迟 <5ms（内存直传，无编码开销）
- 稳定 30fps（不依赖浏览器/网络）
- 单进程故障点少，适合工厂 8 小时连续运行
- 部署简单，PyInstaller 打包成 .exe 即可

## 常见问题（FAQ）

### Q1：LSTM 阈值设多少合适？
默认 0.15。如果步骤经常卡住过不去，降到 0.10；如果误触发太多，升到 0.25。

### Q2：某个步骤总检测不到怎么办？
该动作训练样本太少。标注更多该动作的视频段，重新训练 LSTM。

### Q3：跑到后面变慢了？
检查显存占用（`nvidia-smi`）。关掉其他占显存的程序（剪映、Chrome 等）。

### Q4：`FlashAttention is not available`
这是提示不是错误，可忽略。

### Q5：numpy 版本冲突？
项目使用 `numpy==1.26.4`，与 opencv 的 pip 声明有冲突但实际运行正常。

### Q6：如何接入实时摄像头或 RTSP 流？
修改视频源为 `cv2.VideoCapture(0)`（USB 摄像头）或 `cv2.VideoCapture("rtsp://...")`。
